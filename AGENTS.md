# Руководство для агентов

## Область действия

Этот файл действует для всего репозитория. Перед изменениями сверяйтесь с
`README.md` (назначение и пользовательские сценарии) и `help.MD` (формат
текстурных ресурсов). Если в подкаталоге появится более локальный `AGENTS.md`,
его правила имеют приоритет для файлов этого подкаталога.

## Назначение проекта

Это браузерный набор инструментов для модификации Doom II RPG (J2ME): загрузки
исходного JAR, редактирования карт, скриптов, текстур, палитр и строк, а затем
сборки изменённого JAR. Виртуальная файловая система живёт в памяти браузера;
редакторы должны сохранять изменения в неё, а не обращаться к локальным путям
пользователя напрямую.

Ключевые гарантии продукта:

- 3D-редактор отображает геометрию, спрайты, skybox и BSP-структуру и позволяет
  создавать, менять тип и свойства, перемещать, удалять и сохранять сущности.
  Операции изменения порядка/ID и удаления ссылочных сущностей экспериментальны:
  зависимости скриптов должны быть полностью проверены до атомарной релокации.
- Редактор скриптов поддерживает вставку и удаление инструкций. Любое изменение
  размера байткода должно сохранять корректную релокацию переходов, вызовов
  функций и событий тайлов.
- Редакторы текстур и палитр должны сохранять индексированную природу игровых
  ресурсов, правила прозрачности и совместимость с исходными бинарными
  форматами.
- Текстовый редактор должен учитывать Windows-1251, Windows-1252 и UTF-8.

## Структура и технологии

- Приложение — standalone Angular 21+ с zoneless change detection и Signals;
  точка входа — `index.tsx`, корневой компонент — `src/app.component.ts`.
- UI-компоненты находятся в `src/app/components`, переиспользуемые элементы — в
  `src/app/shared`, состояние и бинарная логика — преимущественно в
  `src/app/services`, константы форматов — в `src/app/core/constants`.
- Three.js отвечает за карту и BSP-визуализацию, Tailwind CSS — за оформление,
  JSZip — за чтение и сборку JAR/ZIP.
- Каталог `java` содержит декомпилированные Java-файлы оригинальной игры и
  сопровождающие материалы реверс-инжиниринга. При разработке SDK **всегда в
  первую очередь сверяйтесь с ними**: реализация, форматы данных, константы и
  игровое поведение в `java/*.txt` являются первоочередным источником истины, а
  `java/help/*.md` помогают ориентироваться в этих материалах. Не трактуйте их
  как исходники, собираемые Angular-приложением.
- Корневые утилиты `dump_script.ts`, `disassemble_static_func.ts`,
  `test_entities.ts` и `doom_texture_extractor.html` предназначены для анализа
  игровых данных и могут не входить в основной browser bundle.

## Правила внесения изменений

- Следуйте существующему стилю: standalone-компоненты, внедрение зависимостей
  через `inject`, Signals для реактивного состояния и небольшие сервисы с чёткой
  ответственностью.
- Не добавляйте Zone.js и не полагайтесь на zone-based change detection.
- Сохраняйте компоненты вкладок смонтированными, если это нужно для сохранения
  состояния и прокрутки; корневой экран намеренно переключает их через
  `hidden`, а не уничтожает условным рендерингом.
- Не дублируйте определения бинарных форматов. Используйте общие `ByteStream`,
  сервисы кодеков, типы и константы проекта.
- При изменениях двоичного чтения/записи проверяйте границы буфера, знаковость,
  порядок байтов и возможность точного round trip без изменения нетронутых
  данных.
- Не коммитьте оригинальные JAR-файлы, извлечённые игровые ресурсы, сборки из
  `dist` или иные защищённые авторским правом бинарные данные.

## Формат текстурных ресурсов

При работе с текстурами соблюдайте описанные в `help.MD` инварианты:

- `newMappings.bin` содержит таблицы mappings, dimensions, bounds, palette
  colors и texel sizes; упакованные размеры являются степенями двойки.
- Цвета `newPalettes.bin` представлены RGB555. Бит `0x8000` в записи палитры
  обозначает ссылку на родительскую палитру.
- Размер данных текстуры вычисляется как `(mediaTexelSizes[i] & 0x3FFF) + 1`;
  бит `0x8000` обозначает ссылочную текстуру. Не записывайте отдельные данные для
  ссылок без осознанного изменения модели формата.
- Файлы `texXX.bin`/`imagesXX.bin` разбиты по границе 32768 байт; при переходе в
  следующий файл смещение начинается заново.
- Сжатые спрайты используют колоночный Doom-формат с каталогом указателей в
  конце буфера и маркером конца колонки `0xFF`.
- Индекс 0 прозрачен для сжатых текстур. Для несжатых текстур он обычно является
  обычным цветом, кроме специально определённых групп; не вводите глобальное
  правило прозрачности для всех ресурсов.

## Проверка изменений

Минимальная проверка для изменений приложения:

```bash
npm run build
```

В `package.json` нет общего автоматического тестового скрипта. Для изменений
парсеров, сериализаторов, ассемблера или релокации добавляйте узконаправленные
проверки, когда это возможно, и обязательно выполняйте production build. Для
заметных UI-изменений дополнительно запустите `npm run dev` и проверьте сценарий
в браузере с тестовым JAR, не добавляя этот JAR в репозиторий.
